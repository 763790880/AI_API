# 管理员接入第三方中转站

入口：管理员账号管理 → 添加账号 → 平台 → 第三方中转站。

1. 填写名称，选择 OpenAI 兼容或 Anthropic 兼容协议。
   按对方的请求路径判断：`/v1/chat/completions` 属于 OpenAI 兼容，`/v1/messages` 属于 Anthropic 兼容；模型名称包含 Claude 不代表必须选 Anthropic。
2. 填写对方域名和 API Key。域名未带协议时使用 HTTPS，也接受带 `/v1` 的地址；不要粘贴完整的 `/chat/completions`、`/responses` 或 `/messages` 请求地址。
3. 系统通过管理员接口读取上游 `/v1/models`，默认选中返回的模型。可取消不需要的模型；读取失败不会创建账号，修正配置后点击“重新读取模型”。模型列表可读不代表每个模型都支持所选协议，创建后应使用账号的连接测试。
4. 选择同协议的投放分组和并发上限，然后创建。账号列表会显示“第三方中转站”标记；后续使用现有编辑、测试和模型同步功能。

OpenAI 兼容账号使用现有 Chat Completions / Responses 转发链路，Anthropic 兼容账号使用 Messages 链路。同一站点若同时需要两类协议，请分别添加两个账号并绑定各自协议的分组。当前模型读取使用服务器直连；站点必须提供相应格式的模型目录接口。

若服务器开启了上游白名单校验，应先在系统设置的“上游域名白名单”中添加第三方域名；此入口不会绕过服务器出站安全配置。

读取失败时页面会区分登录失效、无管理员权限、地址校验失败、超时，以及上游模型目录返回的 HTTP 状态。上游 HTTP 403 可能来自 Key 权限或服务器出口访问限制，不能仅凭本机能请求就认定服务器也能请求。服务日志中的 `sync_upstream_models_preview_failed` 记录经过清理的原因，`sync_upstream_models_preview_succeeded` 记录模型数量，不记录 Key 或原始响应正文。模型不在此 Key 的目录中时，应先向上游确认模型授权和可用渠道，不能凭调用示例认定模型可用。

账号存储为对应协议平台的 API Key 账号，因此沿用现有调度、并发、错误处理、计费和凭据保护，不需要新建数据库平台。模型映射自动设为所选模型的同名映射；售价继续由管理员的渠道、分组和倍率配置决定，上游目录不会自动覆盖价格。

仅管理员可使用新增入口和模型预览接口。普通用户即使直接请求管理员接口也会被拒绝；用户账号创建接口继续拒绝 OpenAI/Anthropic API Key、Upstream 类型以及 OAuth 中夹带自定义地址的请求。

真实第三方 Key 不包含在测试或示例中。自动化测试使用模拟模型目录及占位凭据，外部站点的实际模型调用需要配置后执行连接测试。
